# Android SDK Upgrade TODO

This file describes the workarounds currently in place for building Clipious
in the NixOS/devenv environment and what an agent needs to do to remove them
once the underlying nixpkgs issues are resolved.

---

## Context — what was fixed and why

### Problem 1 — NDK version mismatch (CXX1104)
**Fixed in**: `android/app/build.gradle`
**Change**: Added `ndkVersion flutter.ndkVersion`

The `local.properties` generated by devenv sets `ndk.dir` to the Nix-provided
NDK 28.2.13676358. Without an explicit `ndkVersion`, AGP 8.6.0 defaults to
26.1.10909125 and the two disagree. Setting `ndkVersion flutter.ndkVersion`
makes the explicit value match the installed NDK.

**When to revisit**: If `FlutterExtension.ndkVersion` in the Flutter SDK
(`packages/flutter_tools/gradle/src/main/kotlin/FlutterExtension.kt`) is ever
updated to a version not matching the Nix NDK, this will break again.

---

### Problem 2 — SDK directory is read-only (build-tools auto-install)
**Fixed in**: `android/gradle.properties`
**Change**: Added `android.builder.sdkDownload=false`

The Nix store is immutable. AGP tries to install missing SDK components via
sdkmanager into `sdk.dir`, which fails. This flag disables all sdkmanager-
driven downloads.

**When to revisit**: Can be removed once the devenv Android SDK includes all
required components by default (i.e., the other items on this list are done).

---

### Problem 3 — Plugin library projects reference unavailable SDK platforms
**Fixed in**: `android/build.gradle`
**Change**: Added a `gradle.afterProject` hook forcing all `com.android.library`
subprojects to `compileSdkVersion 34` / `buildToolsVersion "35.0.0"`.

Flutter plugins declare their own `compileSdkVersion` values (31, 33, 34, 35).
The Nix SDK only provides `android-34`. Without this override, plugins
referencing unavailable platforms fail.

**When to revisit**: Can be removed once all Flutter plugins in `pubspec.yaml`
declare `compileSdkVersion 34` or higher natively (check each plugin's
`android/build.gradle`).

---

### Problem 4 — aapt2 binary incompatibility with android-35 on NixOS
**Workaround**: Avoid android-35 entirely (see Problem 5 below).

**Root cause**: The aapt2 bundled in nixpkgs `build-tools;35.0.0`
(version `2.19-11948202`) cannot load `android-35`'s `android.jar` in AGP's
resource-link mode. The binary passes simple `aapt2 dump resources` and
`aapt2 link -I` tests but fails inside AGP's `LinkApplicationAndroidResourcesTask`
(the `LoadedArsc.cpp:94` bounds check triggers for android-35's sparse-entry
resource table format).

Additionally, `android.aapt2FromMavenOverride` cannot be set in
`android/local.properties` (Flutter overwrites the whole file on every build)
nor in `$GRADLE_USER_HOME/gradle.properties` (Flutter does not forward
`GRADLE_USER_HOME` to the Gradle wrapper invocation). There is no reliable
injection point for this override without modifying Flutter itself or using
the global `~/.gradle/gradle.properties`.

**How to properly fix** (future agent):
1. Verify nixpkgs has updated build-tools 35.0.0's aapt2:
   ```bash
   SDK=$(grep "^sdk.dir=" android/local.properties | cut -d= -f2)
   $SDK/build-tools/35.0.0/aapt2 version
   # The build ID must be >= 11315950 (AGP 8.6.0)
   # AND the link test must pass:
   $SDK/build-tools/35.0.0/aapt2 link --proto-format \
     -I "$SDK/platforms/android-35/android.jar" \
     --manifest /dev/null --allow-reserved-package-id \
     -o /tmp/verify.apk 2>&1
   # Expected: only manifest parse error, exit 0
   ```
2. If the test passes, remove the `work-runtime` pin (see Problem 5) and
   bump compileSdk/targetSdk to 35.

---

### Problem 5 — work-runtime 2.10.x requires compileSdk 35 (triggers aapt2 bug)
**Fixed in**: `android/app/build.gradle`
**Change**: Added `configurations.all { resolutionStrategy { force 'androidx.work:work-runtime:2.9.1' } }`

`workmanager_android` 0.9.0+2 hardcodes `work-runtime:2.10.2` which requires
`minCompileSdk = 35`. Since android-35 triggers the aapt2 bug (Problem 4),
we force the transitive dependency back to `2.9.1` — the last release that
only requires compileSdk 34. The public API used by `workmanager_android` is
unchanged between 2.9.x and 2.10.x.

## Upgrade checklist (for a future agent)

### Step 1 — check if nixpkgs aapt2 is fixed

```bash
SDK=$(grep "^sdk.dir=" android/local.properties | cut -d= -f2)
AAPT2="$SDK/build-tools/35.0.0/aapt2"
$AAPT2 version
# Expected: build ID >= 11315950

$AAPT2 link --proto-format \
  -I "$SDK/platforms/android-35/android.jar" \
  --manifest /dev/null --allow-reserved-package-id \
  -o /tmp/verify.apk 2>&1
# Expected: only "/dev/null:1: error: no element found." — exit code 0
```

If both pass, proceed. Otherwise stop — the root issue is still present.

### Step 2 — remove the work-runtime pin

In `android/app/build.gradle`, delete the entire `configurations.all { resolutionStrategy { ... } }` block.

### Step 3 — bump compileSdk / targetSdk to 35 (or higher)

In `android/app/build.gradle`:
- `compileSdkVersion 35`
- `targetSdkVersion 35`

In `android/build.gradle` (`gradle.afterProject`):
- `compileSdkVersion 35`

In `devenv.nix`:
- Add `"35"` to `android.platforms.version`

### Step 4 — run the build

```bash
flutter build apk --debug --split-per-abi
```

Should complete without aapt2 or AAR metadata errors.

### Step 5 — clean up gradle.afterProject if plugins have caught up

If all Flutter plugins now declare `compileSdkVersion >= 35` natively, the
`gradle.afterProject` block in `android/build.gradle` can be removed.
Test by temporarily removing it and checking for "Failed to find target" errors.
